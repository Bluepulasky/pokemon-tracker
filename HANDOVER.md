# Handover

This repository was built to be owned by someone else. It has no remote configured and
nothing ties it to the machine it was written on.

## Recommended: git bundle

A **git bundle** is a single file containing the entire repository *including its
history*. The maintainer clones from it exactly as he would from a server, then points
`origin` at his own remote. Better than a zip: real history, verifiable checksum, one
file, and it moves fine over Syncthing, a USB stick, or `scp`.

### Producing it

```bash
make bundle
# → dist/tombot-pokemon-tracker.bundle
#   dist/tombot-pokemon-tracker.bundle.sha256
```

Send both files.

### Receiving it

```bash
shasum -a 256 -c tombot-pokemon-tracker.bundle.sha256
git clone tombot-pokemon-tracker.bundle tombot-pokemon-tracker
cd tombot-pokemon-tracker

git remote set-url origin git@github.com:<his-user>/<his-repo>.git
git push -u origin main
```

From then on it is an ordinary repo owned by him. The bundle can be deleted.

### Sending updates later

If work continues here after the handover, an **incremental** bundle carries only the
new commits and is a few kilobytes:

```bash
git bundle create dist/update.bundle <last-shared-commit>..main
```

He applies it with:

```bash
git pull /path/to/update.bundle main
```

## Alternatives

**Direct push.** If he adds a deploy key or grants access to an empty repo, this is one
command and the cleanest option:

```bash
git remote add origin git@github.com:<his-user>/<his-repo>.git
git push -u origin main
```

**Zip.** Works, but loses history and gives no integrity check. Only if git is not
available on his side:

```bash
git archive --format=zip --prefix=tombot-pokemon-tracker/ -o dist/tombot.zip HEAD
```

**Direct install on his server.** The repo is self-contained; `docker compose up -d
--build` plus `flask bootstrap` is the whole install. Nothing needs to come from this
machine except the source.

## What is NOT in the repository

Deliberately gitignored, and none of it should be shipped:

- `data/pokemon.db` — his collection is his own data
- `media/catalog/` — ~40 MB of catalog images, regenerated by `flask import-catalog`
- `media/collection/`, `media/thumbs/` — personal photos
- `.env` — API keys and `APP_TOKEN`
- `.venv/`

A fresh clone plus `make install && make bootstrap` reproduces everything except the
collection itself.

## Migrating an existing collection

If the app has already been run here and the collection should move with it, copy the
two runtime directories separately from the source:

```bash
tar czf tombot-data.tgz data/pokemon.db media/collection media/thumbs
```

Extract into the repo root on the target and restart. Do not put this in the bundle —
it is data, not code, and it will be out of date the moment he adds a card.

## First run on his side

```bash
cp .env.example .env          # optional: free key from https://dev.pokemontcg.io/
make install
make bootstrap                # ~1,100 cards; re-run if a set fails, it resumes
make run                      # http://127.0.0.1:8080
```

Then add the monthly price job:

```cron
0 4 1 * *  cd /srv/tombot-pokemon-tracker && docker compose exec -T app flask monthly
```
